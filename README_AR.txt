الإصدار 1.5.62 — إضافة لوحة «كشف حالة الطلب»
- شاشة إدارية مؤمنة لمراقبة الطلبات المتأخرة، وفحص رقم الطلب الداخلي أو رقم المزود، وقوائم المكتملة والملغاة.
- رسائل استفسار/تسريع/إلغاء جاهزة للنسخ فقط؛ لا يجري إلغاء أو استرداد مالي تلقائياً.
- الفحص الخارجي اختياري، وإذا تعذر اتصال المزود تبقى الحالة المخزنة واضحة مع تحذير.
- مراقبة دورية بالخادم (الإصدار الحالي كل دقيقة)؛ يتطلب الإرسال الحقيقي TELEGRAM_BOT_TOKEN جديداً وTELEGRAM_CHAT_ID صالحاً أو إعدادات Telegram آمنة.
- كل ملفات الإصدار (واجهة وخادم وversion.txt وBUILD_ID.txt وpackage.json وconfig.json) تستخدم BUILD_ID واحداً حتى يكتشف /api/health أي نشر جزئي.

إضافات الإصدار 1.5.62 — إصلاحات هذه الحزمة:
- نقل زر واتساب العائم إلى أعلى من شريط الإصدار وأزرار أسفل الشاشة على الموبايل.
- إصلاح تطبيع استجابة المزود عندما ترجع الخدمات ككائن مفاتيحه هي أرقام الخدمات، حتى لا تُفقد الخدمات التي لا تكرر رقمها داخل السجل.
- عرض جميع أقسام المزود المسترجعة في قائمة الأقسام، مع إظهار عدد خدمات كل قسم.
- إضافة زر «عرض المزيد من الخدمات» في قائمة الطلب؛ القائمة لم تعد تقف عند أول 150 خدمة.
- جعل صورة القسم المختارة هي الصورة المعتمدة للخدمات التابعة للقسم حتى لو كانت الخدمة تحتوي أيقونة منصة قديمة، مع الحفاظ على صورة الرفع في بيانات القسم بدلاً من تكرار ملف كبير مع كل خدمة.
- توحيد رقم الإصدار ومعرّف البناء في الواجهة والخادم والملفات المساعدة.

إضافات الإصدار 1.5.62:
- مكتبة صور مضمّنة داخل كود الواجهة: 10 أيقونات منصات و7 صور لأنواع الخدمات، دون الاعتماد على روابط صور خارجية.
- اختيار صورة من المكتبة عند استيراد الخدمات وتطبيقها على القسم وكل الخدمات التابعة له، مع تأثير حركة خفيف ومعاينة للصورة.
- تحسين الرجوع إلى الأيقونة المضمّنة عند وجود صورة قديمة مكسورة أو رابط صورة غير صالح.
- شحن Binance Pay: الحفاظ على هوية وصورة Binance Pay والخطوات الكاملة، مع زر واتساب برسالة جاهزة بالمبلغ؛ لا يظهر Binance ID ولا يوجد حقل TXID داخل الموقع ولا تُضاف الأموال تلقائياً قبل تحقق الدعم.
- صور الخدمات: عرض أيقونة المنصة الصحيحة لكل خدمة، مع إبقاء صورة القسم المخصصة على القسم نفسه.
- استيراد قسم مزود: عند اختيار «قسم كامل» يتم تحديد واستيراد كل خدمات القسم المصدر، مع بقاء خيار تحديد خدمات بعينها.
- الكمية: إدخال يدوي مع توضيح الحد الأدنى والأقصى والتحقق من النطاق قبل إرسال الطلب.
- الأسعار: إعداد هامش ربح عام لخدمات المزود وتحديث تلقائي دوري من سعر التكلفة الأصلي؛ تُتجاوز الخدمة إذا لم يصل سعر موثوق لمنع تغيير السعر إلى صفر أو تراكم الهامش. تحديث Firebase يكتب حقول السعر وحدها ولا يستبدل بقية بيانات الخدمة.
- استيراد الأقسام: قائمة مزود مُقسّمة إلى صفحات، مع تحديد جميع خدمات القسم فعلياً أو إلغاء خدمات محددة، وتصفية المنصة داخل القسم لمنع اختلاط الخدمات.
- الطلبات: ترقيم تسلسلي رقمي، مع ترقيم إضافي للطلبات القديمة دون تغيير مفاتيح قاعدة البيانات أو أرقام طلبات المزود، وتحسين بسيط لحركة بطاقات الطلبات.
- توحيد معرّف البناء بين الواجهة والخادم وملفات الإصدار.

ملاحظة تحديث آمن: احتفظ بمجلد data الحالي وأي Railway Volume الموجودين في بيئة الإنتاج. لا تستبدل بياناتك بملفات افتراضية من الأرشيف.

ملفات التشغيل: index.html, server.js, package.json, railway.json, config.json, version.txt, BUILD_ID.txt, api-addon.js وأصول الصور.
النشر: فك ضغط الملف داخل جذر المشروع المرتبط بـ Railway واستبدل ملفات التطبيق، واحتفظ بمجلد data والـ Railway Volume الحاليين. إذا كان المشروع مربوطاً بـ GitHub، احفظ وادفع التغييرات لبدء نشر جديد. بعد اكتمال النشر افتح /api/health?ts=رقم-جديد وتأكد من version=1.5.62 وdeploymentConsistent=true.

فحوصات الإصدار: فحص صياغة سكربتات JavaScript والخادم، واختبارات منطقية لاستيراد الأقسام وتصفية المنصات وحساب هامش الربح وحدود الكمية وترقيم الطلبات، وفحص تشغيل الخادم والحزمة المضغوطة. هذه فحوصات محلية ولا تعني أن المشروع تم نشره أو أن API المزود الحقيقي تم اختباره من هذه البيئة.

إضافات الإصدار 1.5.62:

الإصدار 1.5.64 — WhatsApp + Telegram + Google Auth
- زر واتساب: يُنقل إلى body مباشرةً، مع z-index عالٍ جداً وخلفية معتمة ومقاس ثابت، ويختفي عند فتح النافذة المنبثقة حتى لا يغطي عناصرها.
- Telegram: إشعار طلب جديد إلى الوجهة الأساسية المحددة في TELEGRAM_CHAT_ID، ويمكن إضافة وجهات مستقلة عبر TELEGRAM_EXTRA_CHAT_IDS. مراقب الطلبات يعمل كل دقيقة، ويصعد التحذير عند 3 و6 و12 ساعة للطلبات غير النهائية، مع حفظ علامة كل مستوى لتفادي التكرار.
- حماية التوكن: لا يوضع بوت توكن داخل HTML أو الحزمة؛ ضع توكناً جديداً بعد إلغاء التوكن المكشوف داخل Railway Variables باسم TELEGRAM_BOT_TOKEN. اجعل TELEGRAM_CHAT_ID=@hddjh55 وأضف البوت كمسؤول قادر على نشر الرسائل في القناة. الرقم الذي يسبق النقطتين في البوت توكن هو Bot ID وليس بالضرورة Chat ID للمحادثة.
- تسجيل Google: تحقق الخادم من ID token باستخدام Google Auth Library ولا يثق في بيانات يرسلها المتصفح وحدها. يحتاج GOOGLE_CLIENT_ID من Google Cloud OAuth Web Client، وإضافة https://3dce.up.railway.app إلى Authorized JavaScript origins.
- CAPTCHA: سؤال جمع صغير مرتبط بجلسة/عنوان الشبكة، أحادي الاستخدام، بمدة صلاحية خمس دقائق، مع تحديد معدل الطلبات.
- التخزين: لحفظ ملفات الحسابات والحالات بين إصدارات Railway، اربط Volume دائمًا أو تأكد من صلاحية الكتابة إلى Firebase.
